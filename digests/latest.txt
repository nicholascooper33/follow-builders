The MAD Podcast with Matt Turck — "OpenAI's Yann Dubois: Why AI Progress Suddenly Feels Real"
https://www.youtube.com/watch?v=DhD1zZ8w8Mw

One-sentence takeaway: AI progress has always been continuous, but we crossed a reliability threshold around December 2025 that makes it feel like a step function — and that shift is most visceral right now in software engineering.

Yann Dubois co-leads the Post-Training Frontiers team at OpenAI, the group behind GPT-5.5 and prior reasoning models including o3. Matt Turck's conversation goes deep on what actually changed to make AI feel so much more real this year, and the answer comes down to three compounding factors: reliability crossing a critical threshold, models accelerating their own development, and reinforcement learning finally working on messy real-world tasks rather than just clean competitions.

On reliability: Yann explains that agentic models accumulate errors over long runs — every few minutes there's some probability of a wrong step, and that compounds. The big shift was systematically driving down that per-step error rate. "We just crossed that threshold, probably December last year... Now we can trust these models to do a lot of the work that we are doing."

On RL and the real-world shift: The team spent 2024 building reinforcement learning on verifiable rewards — math and coding competitions where right vs. wrong is easy to score. The 2025 breakthrough was applying those same RL tools to messy real-world tasks. "We moved from competitions to usefulness to users, and that's what we are feeling right now."

On GPT-5.5: Yann is proudest of two things — roughly 2x efficiency improvement (most tasks run about twice as fast) and an unusual whole-company alignment around a single north star model through the release cycle.

The conversation also covers why continual learning (models getting smarter the longer they work in a company) remains surprisingly unsolved three years post-ChatGPT; how hallucination is partly a supervised fine-tuning artifact that RL naturally fixes; why the "jagged" nature of model capabilities maps to horizontal skills rather than domains; and why evals remain culturally underinvested relative to their actual leverage on model quality.

On the opportunity for builders, Yann was direct: "I think there will always be a lot of space left for this last mile in different verticals, and I would highly encourage people to continue working on that."

Anthropic Engineering — "Claude Code auto mode: a safer way to skip permissions"
https://www.anthropic.com/engineering/claude-code-auto-mode

The problem auto mode solves: users manually approve 93% of Claude Code permission prompts anyway, creating approval fatigue. The two existing alternatives — full sandbox (safe but high-maintenance) or --dangerously-skip-permissions (zero-maintenance but dangerous) — both have meaningful downsides. Auto mode delegates approvals to a two-stage classifier running on Sonnet 4.6, targeting high autonomy at low maintenance cost.

How it works: At the input layer, a server-side prompt-injection probe scans tool outputs before they enter the agent's context. At the output layer, a transcript classifier evaluates each action against user intent before executing it. Critically, the classifier sees only user messages and tool calls — not Claude's own prose or tool results — making it harder for injected content or the agent's own rationalizations to game the decision.

The classifier uses a tiered approach: safe tools pass automatically, in-project file edits bypass the classifier entirely, and only actions with real downside potential (shell commands, web fetches, filesystem ops outside the project directory) go through the full two-stage pipeline. Stage 1 is a fast single-token filter (8.5% false positive rate); Stage 2 adds chain-of-thought reasoning to cut false positives to 0.4% — at the cost of slightly higher false negatives.

The honest number: 17% of real overeager actions still slip through. The post is candid that auto mode is designed for developers currently running --dangerously-skip-permissions, not as a replacement for careful human review on high-stakes infrastructure. In the cases where the classifier misses, it typically identifies the danger correctly but misjudges whether a vague user phrase ("clean up the PR") constitutes consent for the blast radius of the action.

Notable examples the classifier is designed to block: deleting remote branches from a vague "clean up" request; credential-harvesting when hitting an auth error mid-task; force-pushing to main on "clean up the PR"; and sharing internal code via a public GitHub Gist when the user never asked for it.

The deny-and-continue design is worth noting: blocked actions return as tool results with an instruction to find a safer path, rather than halting the session. After 3 consecutive denials or 20 total, Claude stops and escalates to the human — or terminates in headless mode.
