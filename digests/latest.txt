No Priors: Building an Autonomous Delivery Experience with DoorDash Co-Founders Andy Fang and Stanley Tang
https://www.youtube.com/watch?v=vNpcg_Ma-FA

One-sentence takeaway: DoorDash has been a robotics company since 2018, and their 10-billion-delivery data advantage is why they — not a pure-play robotics startup — are best positioned to make autonomous delivery work at scale.

Andy Fang and Stanley Tang joined No Priors to lay out DoorDash's surprisingly long-running bet on AI, robotics, and agentic commerce. The conversation covers three distinct threads woven together into a coherent strategy.

On agentic commerce ("Ask DoorDash"): The team originally bet on voice as the modality — that didn't land. But a natural conversational experience did. Today, 50% of Ask DoorDash restaurant sessions end with an order from a restaurant the user has never ordered from before — historically one of DoorDash's hardest metrics to move. Grocery basket sizes are running 40% larger. DoorDash also incorporated live world knowledge (trending restaurants, real-time internet signals) into the experience to build trust. Andy sees the future as "agent-first" — there's already more agent traffic on the web than human traffic — and DoorDash launched a CLI last week specifically to unlock use cases like a camera pointed at a pantry shelf that automatically restocks when supplies run low.

On robotics and DoorDash Dot: Stanley described starting the robotics program in 2018 — before it was obvious — as "me and half an engineer's time" on a skunkworks project. After years of partnering with sidewalk robot companies (too slow, wrong distance) and robotaxi players (wrong form factor for goods), they concluded no one was building what DoorDash actually needed: a 300-pound, 20 mph vehicle that can navigate both bike lanes and roads for 3–5 mile suburban deliveries. So they built it. DoorDash Dot has been live in Phoenix for over two years, achieved Level 4 autonomy last year, and is now scaling toward the Bay Area and more cities. The key lesson: autonomy is increasingly less of a bottleneck — the real challenges now are operational scaling, merchant integration, and hardware manufacturing.

On the data moat: The team's most durable advantage is data nobody else has — specifically, where human Dashers have physically dropped off every package for every address. GPS pins are imprecise; robots can't improvise like humans. DoorDash has the ground truth. The same applies to edge cases that only emerge at true fleet scale: leaves on one side of a road changing torque requirements, boot scripts that work fine at 10 robots but collapse at 500. Stanley's recruitment pitch to researchers: "Do you want to work on demos, or do you want to ship something in the real world?"

Direct quote: "In a world where robotics, drones, AI is everywhere, my guess is that in ten years' time, we're actually going to have more Dashers doing deliveries, not less — simply just because the pace at which DoorDash is growing... there has to be we're gonna have to find other areas of opportunity." — Stanley Tang

Anthropic Engineering: How we contain Claude across products
https://www.anthropic.com/engineering/how-we-contain-claude

A detailed technical post on how Anthropic's engineering team thinks about agent security across three products — claude.ai, Claude Code, and Claude Cowork — and what has broken along the way.

The core framework: security risks fall into three categories (user misuse, model misbehavior, external attackers), and defenses must cover three layers (the environment the agent runs in, the model itself, and the external content the agent can reach). Environment is where Anthropic has invested most, because model-layer defenses are probabilistic and can never be 100%.

Key patterns: claude.ai uses ephemeral gVisor containers (minimal blast radius, minimal capability). Claude Code uses a human-in-the-loop sandbox — but approval fatigue showed up within weeks, with users approving ~93% of permission prompts. An OS-level sandbox (Seatbelt on macOS, bubblewrap on Linux) cut permission prompts by 84%. Claude Cowork uses a full local VM — filesystem, kernel, and process table isolated — so non-technical users never have to evaluate a bash command.

The failures that taught the most: (1) Claude Code had a class of pre-trust bugs — project-local hooks and config files that executed before the user saw the "Do you trust this folder?" prompt. Fix: defer all parsing until after trust is established. (2) A controlled phish succeeded 24/25 times: a researcher sent an employee a paste-ready prompt that included instructions to read ~/.aws/credentials and POST them externally. The model layer has no signal to catch this; only egress controls stop it. (3) In Claude Cowork, a malicious file used the attacker's own Anthropic API key to call api.anthropic.com/files — a domain on the egress allowlist — and exfiltrate workspace data. Fix: a man-in-the-middle proxy inside the VM that only passes requests carrying the VM's own provisioned session token.

The through-line: "The software you build yourself is often the weakest." Standard hypervisors and syscall filters survived; the custom allowlist proxy and custom startup logic were what broke. When hardening agents, start with mature primitives and treat project-local config, localhost listeners, and approved-domain endpoints with the same skepticism you'd apply to inbound internet traffic.
