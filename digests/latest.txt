AI & I by Every — "Microsoft's Vision for an Internet Made for Agents With CTO Kevin Scott (Best of the Pod)"
https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

Takeaway: Microsoft CTO Kevin Scott argues we are at the same inflection point for AI agents that the early web was for documents — and that MCP is to the agentic web what HTTP was to the internet.

In this wide-ranging conversation with Dan Shipper (CEO of Every), Scott explains why this year's big theme at Microsoft Build shifted from scaling laws to the "agentic web." Last year, people were questioning whether scaling would continue; today that's settled. The new challenge is closing the gap between what models can do and what we're actually using them for — what Scott calls the "capability overhang."

Scott identifies two core problems holding agents back: memory and access. Current agents are transactional — they handle one task coherently but often start from scratch the next session, which limits how much you can delegate. And for agents to be truly useful, they need to take action across diverse systems. That requires an ecosystem of open protocols, much like the web. He's enthusiastic about MCP precisely because it's "so coherently simple" — a lightweight protocol that lets agents connect to any service, the same way HTTP lets browsers connect to any website.

On security, Scott doesn't claim to have all the answers but sees agent identity and entitlement systems as relatively tractable problems to build on top of MCP. He envisions agents that can query what permissions they need before acting, then surface that to the user for approval — rather than having broad ambient access.

Asked about the future of software engineering, Scott pushes back on the idea that AI agents diminish craft. He's been programming for 41 years and has seen this debate many times: power tools vs. hand tools, CNC vs. manual woodworking. His advice: "Be curious. Try. And if it works for you, use it." He predicts the next big shift will be from synchronous to asynchronous agent interaction — you'll delegate a multi-hour task, the agent will make dozens of calls across systems, and come back later with a result.

Direct quote: "Like if agents are gonna be useful, they have to take action on your behalf. They have to be able to use tools and make changes in systems and consult information sources that are diverse and rich. In order for that to really be great, you need an ecosystem that looks a lot like the Internet."

Anthropic Engineering — "An update on recent Claude Code quality reports"
https://www.anthropic.com/engineering/april-23-postmortem

Anthropic published a detailed postmortem on three separate changes that degraded Claude Code quality for some users over the past month, all now resolved as of April 20 (v2.1.116). The three issues were: (1) a default reasoning effort downgrade from high to medium that reduced intelligence; (2) a caching optimization bug that caused Claude to progressively lose reasoning history mid-session, leading to apparent forgetfulness and unusual tool choices; and (3) a system prompt change to reduce verbosity that unexpectedly hurt coding quality. Because each change affected different traffic slices on different schedules, the aggregate effect looked like broad inconsistent degradation. As of April 23, Anthropic is resetting usage limits for all subscribers. Going forward, they are increasing internal use of public builds, expanding eval coverage for system prompt changes, and adding tighter soak periods and gradual rollouts.

Anthropic Engineering — "Scaling Managed Agents: Decoupling the brain from the hands"
https://www.anthropic.com/engineering/managed-agents

Anthropic's engineering team explains the architectural evolution behind Claude Managed Agents, drawing a direct analogy to how operating systems virtualized hardware into durable abstractions. The key insight: coupling the agent "brain" (Claude + harness), "hands" (sandbox execution environments), and "session" (event log) into a single container created a fragile "pet" that was hard to debug and couldn't scale. The new architecture separates all three. The harness now calls sandboxes as tools (execute(name, input) → string), meaning container failures surface as tool errors Claude can handle. Sessions are stored outside the harness, so a harness crash just means rebooting with wake(sessionId). Security improved because credentials never reach the sandbox. Performance improved dramatically: p50 time-to-first-token dropped ~60% and p95 dropped over 90%, since containers are only provisioned when actually needed. The piece also covers how this enables "many brains, many hands" — parallel agents coordinating across multiple sandboxes.

Claude Blog — "New in Claude Managed Agents: self-hosted sandboxes and MCP tunnels"
https://claude.com/blog/claude-managed-agents-updates

Anthropic announced two new enterprise capabilities for Claude Managed Agents. Self-hosted sandboxes (public beta) let agent tool execution run on infrastructure the customer controls — whether their own servers or managed providers like Cloudflare, Daytona, Modal, or Vercel — keeping sensitive files, code, and data within the enterprise perimeter. The orchestration and context management layer stays on Anthropic's infrastructure while only the execution moves. MCP tunnels (research preview) let agents connect to private MCP servers inside a company's network without exposing them to the public internet, via a lightweight outbound-only gateway. Early adopters include Clay (GTM engineering agent on Daytona), Amplitude (design agent on Cloudflare), and Rogo (institutional finance analyst agent on Vercel Sandbox).
