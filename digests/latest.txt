GitHub's COO Explains Why AI Hasn't Replaced Developers
AI & I by Every | Published 2026-06-17

Takeaway: GitHub COO Kyle Daigle reveals that 17 million pull requests were created by AI agents in March alone — and that GitHub is preparing for a wave of growth that shows no sign of plateauing.

Mike Taylor (Every's head of tech consulting) sat down with Kyle Daigle at a developer conference for a wide-ranging conversation on the agent economy from GitHub's uniquely positioned vantage point. GitHub saw 1 billion commits in all of 2024; at current growth rates, they are on track for 14 billion this year. The 17M agent-created pull requests in March are "just the agent PRs" — on top of all human-created ones. Daigle pushes back on the "slop" narrative: the code volume is real and represents genuine developer leverage, not noise.

On business model evolution, Daigle draws a parallel to GitHub's old private repo shift: just as individuals eventually deserved free private repos, the question now is what baseline level of agent usage every developer deserves by default. The answer will emerge from usage data, not top-down policy. He explicitly named Peter Steinberger's 150-simultaneous-agents workflow as the extreme end of what GitHub wants to enable — for those willing to pay for it.

On open source maintainer burnout from the PR flood, GitHub is investing in agentic code review (which can now handle its own suggested fixes end-to-end) and giving maintainers more control over who can submit PRs at all — without mandating any single community standard.

Perhaps the most vivid part of the conversation: Daigle's personal AI loop. He feeds everything he says and writes into a personal agent he calls Baxter (an OpenClaw instance), which reads his last seven days of emails and Slack messages and gives him a communication improvement report — not a summary of what he said, but patterns and metaphors he overuses. "Humans are way more willing to take critical feedback from robots than other humans," he noted, citing GitHub's old Hubot chatops days. His agent loop is primarily about self-improvement, not code.

On the $200-to-$2,000 cost spiral: the answer is model routing by task intent. Auto-routing a find-and-replace to a smaller model while reserving frontier models for hard problems is the lever — but developers won't do it manually. GitHub and Microsoft Foundry are building that router layer so the system can choose.

Direct quote: "The thing that I think seems to be true from the beginning to OpenClaw to now is this idea of personalization — or mine, or context, or fine tuning with context, or memory. All of these ideas seem to be a truth that's been there since ChatGPT came out or GitHub Copilot came out."
