The MAD Podcast with Matt Turck
"The Biggest Chip Ever Built — Why OpenAI Runs On It | Cerebras CEO Andrew Feldman"
Published: July 23, 2026

One-sentence takeaway: Inference speed — measured in tokens per second per user — has become the dominant competitive axis in AI, and Cerebras built the chip that wins it by making a silicon architecture bet in 2016 that nobody else would make.

Matt Turck sat down with Andrew Feldman, cofounder and CEO of Cerebras, fresh off what may be the largest semiconductor IPO in history and a $20B+ deal with OpenAI. The episode is a rare bottom-up primer: it starts from "what is a wafer" and builds up through why GPUs struggle with fast inference, three hardware shortages nobody talks about, a decade in the desert where nobody wanted the product, and why CUDA may no longer be NVIDIA's moat.

The core technical insight: inference is fundamentally different from training. To generate each word, a model must move its entire weight set — equivalent to 100 HD movies for a 70B parameter model — from memory to compute, then repeat for the next word. GPUs use HBM (high bandwidth memory), which is slow for this movement. Cerebras chose SRAM — far faster, but limited in capacity — then solved the capacity problem by building the largest chip in computing history: a single silicon wafer, 46,000 mm² (versus 840 mm² for the previous record), stuffed with SRAM. It processes inference 2,500 times faster than an equivalent GPU on that memory-movement step.

Feldman argues CUDA's moat is shrinking fast: Gemini is trained on TPUs, Claude is trained on Trainium, OpenAI uses its own silicon. Two or three years ago CUDA had near-100% share of state-of-the-art training — today that's gone. On inference: "There's no moat in inference. It takes you eight keystrokes to move from a GPU to us in the cloud."

The episode covers three current hardware bottlenecks (HBM shortage, CoWoS packaging shortage, 3nm factory congestion — Cerebras avoids all three), why agentic AI is creating a CPU shortage as agents make calls that CPUs must execute, the deep-tech "Everest" problem that nearly sank the company during 18 months at $8M/month burn while solving packaging no one had done before, the OpenAI deal structure (750 megawatts of data center capacity deployed across 2026–2028), and why Feldman believes this is not a bubble.

Direct quote on why speed is everything: "How big is the market for slow search? How big is the market for dial-up? It's zero. How long will you wait for a website to resolve? Nobody waits. And so it's the exact same with AI."

Claude Code now supports artifacts — Claude Blog
Published: Jun 18, 2026

Claude Code can now turn session work into live, shareable visual web pages called artifacts — PR walkthroughs, system explainers, dashboards, and release checklists that update in place as the session progresses. Built from the full context of a session (codebase, connected tools, conversation), artifacts need no separate infrastructure. Every publish goes to the same URL with teammates seeing updates instantly and full version history available.

A key internal use case: incident investigation. An engineer kicks off an investigation before standup, Claude Code publishes an artifact with a timeline, suspect commits, and an error-rate chart. She shares the link. By standup, Claude has republished it twice as the investigation progressed — so the whole team is looking at the same live view, with the same context, without anyone needing to summarize what the agent found.

Artifacts are private to the author by default, shareable to org members, and never public. Admins get org-wide visibility via a compliance API, role-based scoping, and retention policies. Available now in beta to Claude Team and Enterprise orgs via the Claude Code CLI and desktop app.
