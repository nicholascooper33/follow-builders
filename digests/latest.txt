Training Data: Memory and Continual Learning — Engram's Dan Biderman and Jessy Lin
https://www.youtube.com/watch?v=aiR7F4jqjXY

The bottleneck for making AI models more useful is no longer raw intelligence — it is the ability to learn and retain new, domain-specific context that never made it into pre-training data.

Dan Biderman and Jessy Lin are the cofounders of Engram, a research lab focused on memory and continual learning. Their core thesis: context engineering and RAG are useful but underleverage an available tool — the same training pipeline frontier labs use to make models great at math or code can be applied to private, domain-specific data. "Models are always training" is Engram's founding principle, and they are building toward per-team adapter-fine-tuned models (LoRAs, prefix tuning, sparse architectures) that continuously improve on real workspace data from partners like Notion, Microsoft, and Harvey.

The conversation gets into the RAG-vs-weights debate at length. Engram's view is that it is a false dichotomy — both matter, but certain things can only live in weights. Specifically: the associative connections that let a model say "I notice you're researching X; here's something related you didn't ask for." That kind of recall is not a lookup; it emerges from training. Jessy Lin puts it concretely: a model trained on your team's context can answer in 100 tokens what the best frontier model would spend 100,000 tokens retrieving and reasoning about. That is a two-orders-of-magnitude token reduction — not a rounding error.

There is also a fascinating technical aside about KV cache efficiency. A single Wikipedia article produces ~80 GB of KV cache for a 70B model, while the entire weights of that model — which effectively "remember" the whole internet — are only ~100 GB. Engram's research is exploring whether that 80 GB cache could be compressed 1000x by training it into weights offline, with major implications for inference speed and memory footprint.

The long-term vision: a world where everyone has their own personalized model — trained on their own data, fine-tuned for their own workflows — and where the more time you spend on a task, the better your model gets at it. As Jessy put it: "I'm imagining a world where everyone has their own model that is really different from the other person's model and from the frontier model, and all of these serve different purposes."

Dan comes from neuroscience and draws a useful analogy: human memory evolved to be lossy precisely because intelligence requires compressing what is important. The real research question is not facts vs. skills — that distinction breaks down under gradient descent — but what deserves to be internalized vs. externalized, and how to make that judgment automatically.

Direct quote from Dan Biderman:
"Now to figure out how to crack this problem of continual learning, it's about figuring out what about pre-training or even post-training makes it possible for the models to generalize in these magical emergent ways — and controlling that process so that a company has a set of private data. How do we make the models learn that just as well as the models know the capital of France or how to write Python?"

Claude Blog: Claude Code now supports artifacts
https://claude.com/blog/artifacts-in-claude-code

Claude Code can now generate live, shareable visual pages — called artifacts — directly from a session's context. These are not static exports; they update in place as the session progresses, and every publish creates a versioned snapshot at the same URL. Use cases include PR walkthroughs, incident timelines, data dashboards, dependency audits, and release checklists. The artifact is built from everything Claude Code already has access to: your codebase, connected monitoring tools, and the conversation itself. All artifacts are private to the author by default, shareable within an org, and managed via role-based access controls and a compliance API. This closes a gap that has always existed in AI-assisted engineering: turning what the agent found into something teammates can actually look at together.
