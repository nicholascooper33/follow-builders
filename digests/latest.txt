Peter Steinberger — Polyagentmorous ClawFather, building OpenClaw, partnered with OpenAI
Peter has turned Codex into an automated code-review pipeline on his main branch. Every commit landing on main now spins up a Codex instance that reviews it for regressions and security issues. If a problem is found, a second Codex agent spins up, creates a fix PR, and a review agent evaluates it — looping up to five times. The system went live and found one of his own bugs within 10 minutes. This is a concrete example of agents being woven into CI/CD rather than used as standalone tools.

Dan Shipper — CEO at Every, the AI-focused subscription publication
Dan is experimenting with running PostHog analytics directly inside Codex's in-app browser, and finds it dramatically better than using a standalone browser — Codex can write queries, read results, and kick off agents to write PRs or run production DB queries based on what it finds, all in one context. He's also pushing a new concept: "Codex-native" (or "Cursor-native" / "Cowork-native") apps — software designed to be used inside the in-app browser of your agent, where both the agent and the human share full context and can see each other's actions. He sees this as a large, underexplored opportunity for builders.

Aaron Levie — CEO at Box
Aaron made an extended case for why technical jobs aren't disappearing — quite the opposite. He argues that agents represent the largest leverage multiplier for technical people in history, and that we are about to get 100x more software, not a reduction: legacy systems being replatformed, SMBs that could never hire developers, security vulnerabilities needing patches, IT workflows being automated, and data being connected across organizations. He notes the nuance: agentic coding is fantastic for doing more, but it's not great for casually building complex systems you'll need to maintain long-term — upgrades, security, and maintenance are taxes most knowledge workers aren't prepared for.

Zara Zhang — Builder, Harvard '17
Zara shared two insights that are easy to overlook. First: instead of asking AI to generate images, ask it to generate SVGs — vector illustrations blend seamlessly into design styles and are a perfect complement to HTML-based slides (she demonstrated this using the QuiverAI API inside AnyGen's Frontend Slides feature). Second: she's noticing a shift away from building web apps with GUIs, toward simply sharing GitHub repos with the code — letting people's agents build their own customized version of the UI. It's a provocative rethinking of what "shipping a product" looks like when your users have agents.
