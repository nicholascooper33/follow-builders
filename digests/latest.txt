Swyx — AI engineer and builder at Cognition, co-host of Latent Space podcast

Swyx laid out a four-part AI-native software development lifecycle. Step one: put ~50 tests in place with instructions to keep adding them. Step two: use /plan to break up hot paths, isolate files for easier editing, and add logging and error boundaries. Step three: with the plan in hand, tell the AI it can break backward compatibility and to proceed non-stop, committing and deploying along the way. Step four: periodically spot-check deployed functionality and steer bugs. It's a practical blueprint for letting AI drive large chunks of the build cycle while keeping a human in the loop at key junctures.

Training Data — Rebuilding IT From the Ground Up for the AI Age: Serval's Jake Stauch
https://www.youtube.com/watch?v=j7ypvRUFY7M

Serval CEO Jake Stauch's core thesis is simple: enterprise automation only spreads when building the automation is easier than doing the task manually—and AI finally makes that possible.

Stauch explains that ServiceNow got the core abstraction right (workflows on top of databases) but made building those workflows too expensive: weeks or months of developer time, often outdated by the time they shipped. Serval keeps the same primitives but uses a "cogen engine" that compiles natural language descriptions into working TypeScript automations instantly. Once built, those automations run without regenerating code on every request, which gives Serval unusually strong unit economics compared to most AI companies—they are not in the business of reselling tokens.

On model selection, Serval runs both OpenAI and Anthropic models: OpenAI wins on end-user interactions, while Anthropic's Sonnet and Opus models excel on the automation/code generation side. Stauch was candid about model upgrade friction: "Sometimes you get some advantages, and some things that were working really well don't work as well anymore." In some cases, they have downgraded models because predictable behavior mattered more than raw capability.

Architecturally, Serval uses a two-agent model: an admin agent that builds and configures tools with proper permissions and approvals, and a helpdesk agent that end users interact with—but the helpdesk agent can only use what the admin has explicitly published. This design gives enterprises full agent intelligence while maintaining the control layer that IT, security, and compliance teams require.

Stauch's contrarian view: the real tension in enterprise AI is not between companies and foundation model providers, but between individuals who want full autonomy from their AI tools and organizations that want control. He compared it to the Shadow IT era when employees smuggled iPhones into BlackBerry shops: "The companies that basically say yes as the default are going to be way ahead of the companies that say no as the default."

On building an AI-native company, Serval gives AI "right of first refusal" on every department. They have eliminated solution engineers and SDRs entirely, with reps using Serval to answer technical questions and generate battle cards in real time during calls. Their hiring mantra: "fewer, better"—because the ability to reinvent quickly requires a small, agile team. The company's north star: "We want to be the tool that actually closes the gap between what you think your job's gonna be and what your job actually is."

Anthropic Engineering: Scaling Managed Agents — Decoupling the brain from the hands
https://www.anthropic.com/engineering/managed-agents

Anthropic's engineering team explains the architectural rethink behind Managed Agents. The core insight: virtualize agent components into stable interfaces (session, harness, sandbox) the same way operating systems virtualized hardware decades ago. By decoupling Claude's "brain" (harness + inference) from the "hands" (sandboxes and tools) and persisting the session log outside the harness, the system became resilient to crashes, easier to debug, and flexible enough to connect to customer VPCs. The result: p50 time-to-first-token dropped ~60% and p95 dropped over 90%. The post also covers the security model—credentials are never accessible from the sandbox where Claude's generated code runs, using either token-bundled resource access (for Git) or a secure vault-and-proxy pattern (for OAuth/MCP tools).

Claude Blog: New in Claude Managed Agents — self-hosted sandboxes and MCP tunnels
https://claude.com/blog/claude-managed-agents-updates

Anthropic announced two new Managed Agents capabilities. Self-hosted sandboxes let enterprises keep tool execution inside their own infrastructure or with managed providers (Cloudflare, Daytona, Modal, Vercel), while the agent loop stays on Anthropic's side—keeping sensitive files, packages, and services within the enterprise security perimeter. MCP tunnels allow agents to reach private MCP servers (internal databases, APIs, ticketing systems) without exposing them to the public internet, via a lightweight gateway that makes only a single outbound connection. Self-hosted sandboxes are now in public beta; MCP tunnels are in research preview with access available on request.
